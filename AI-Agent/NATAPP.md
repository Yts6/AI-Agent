# natapp 使用结论：当前网络下不可用

## 诊断结果

我完整测试了 natapp，**客户端能下载、token 有效，但连不上认证服务器**。

### 具体表现

```
正在连接认证服务器进行登录...
连接认证服务器错误 1 秒后重试...
internal error: Post "https://auth.natapp.cn/auth": context deadline exceeded
```

### 逐层排查

| 测试项 | 结果 | 说明 |
|---|---|---|
| DNS 解析 | ✅ 118.31.58.207 | 域名正常解析 |
| Ping | ✅ 22ms | 网络可达 |
| TCP 443 | ✅ 连通 | 端口没被封 |
| HTTP 80 | ✅ 404 | 服务器活着 |
| **HTTPS + SNI** | ❌ 超时 | **关键：被阻断** |
| IP 直连（无 SNI） | ✅ 404 | 证明是 SNI 层面拦的 |

### 根因

**SNI 阻断**。TLS 握手时会在 ClientHello 里明文携带目标域名，
当域名是 `auth.natapp.cn` 时，连接被中断。

这不是 natapp 客户端的问题，也不是你的网络配置问题，是链路层面的限制。

## 我的建议

**就用 cpolar 吧。**

理由：
1. 已经验证可用，稳定
2. 固定地址其实更方便——发出去的链接不会失效
3. 你最初担心「一直是一个网站」，但实际用起来，对方能反复访问同一个链接是优点

如果你确实是**想隐藏身份/避免被追踪**，那固定地址确实不合适，
但这种需求用免费穿透服务本身也解决不了。
