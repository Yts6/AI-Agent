# 性能压测方法论

## 压测工具与场景
压测工具使用 JMeter 和 wrk，JMeter 适合复杂业务链路，wrk 适合纯 HTTP 接口。
压测场景分三类：基准测试（单接口）、容量测试（逐步加压找拐点）、稳定性测试（长时间运行）。
基准测试每次只压一个接口，排除干扰。

## 关键指标
QPS 是每秒处理请求数，是吞吐量核心指标。
TP99 是 99% 请求的响应时间，比平均值更能反映真实体验。
错误率超过 1% 说明系统已到瓶颈，需要停止加压。
资源使用率重点关注 CPU 和内存，CPU 超过 80% 应视为达到容量上限。

## 压测流程
第一步明确目标，比如"验证 5000 QPS 下 TP99 小于 200ms"。
第二步准备数据，避免压测时被数据库拖累，通常预置 100 万条测试数据。
第三步逐步加压，每档压 5 分钟，观察指标是否稳定。
第四步定位瓶颈，结合火焰图和慢查询日志分析。
第五步输出报告，包含压测结论、瓶颈分析、优化建议。
