# 系统架构设计

## 整体分层
系统分为接入层、应用层、领域层、基础设施层四层。
接入层负责限流鉴权和协议转换，使用 Nginx + Lua 实现。
应用层包含订单、支付、库存三个核心服务，服务间通过 gRPC 通信。
领域层沉淀业务规则，采用领域驱动设计（DDD）的聚合根模式。
基础设施层封装数据库、缓存、消息队列等外部依赖。

## 数据流向
用户请求经接入层限流后进入应用层，应用层调用领域层计算结果。
需要持久化的数据写入 MySQL，热点数据同步到 Redis。
异步任务通过 Kafka 投递到消息队列，由消费者服务异步处理。
全链路追踪使用 Jaeger，trace_id 在接入层生成并透传。

## 容量规划
订单服务单实例支撑 800 QPS，峰值时需要扩容到 6 个实例。
MySQL 主从架构，主库读写，从库只读，延迟控制在 50ms 以内。
Redis 集群 3 主 3 从，单节点内存 16G。
