# 接口设计规范

## 命名与版本
所有接口路径使用小写加中划线，例如 /api/v1/order-detail。
版本号放在路径中，不兼容变更必须升级大版本。
资源名用复数，操作通过 HTTP 方法表达，禁止在路径中使用动词。

## 错误码约定
错误码为 5 位数字，前两位表示业务域，后三位表示具体错误。
订单域使用 10 开头，支付域使用 20 开头，用户域使用 30 开头。
所有错误响应必须包含 code、message、trace_id 三个字段。
HTTP 状态码语义化：400 参数错误，401 未认证，403 无权限，429 限流，500 服务端错误。

## 限流与超时
对外开放接口默认限流 100 QPS，按 IP 维度。
内部服务间调用超时设置：读接口 500ms，写接口 1500ms。
重试策略：只对幂等接口重试，最多 2 次，采用指数退避，间隔 100ms 起。

## 分页
统一使用游标分页，不使用 offset 分页。
游标由服务端生成，客户端透传，禁止客户端解析游标内容。
单页最大返回 100 条，默认 20 条。
